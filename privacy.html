1. Overview and Application Scope

This Privacy Policy applies to the Meta developer application “NEWS SNAP Auto Publisher”, operating in conjunction with the open-source automation pipeline hosted at github.com/hafizabdulbar3-creator/news-snap-automation.

NEWS SNAP Auto Publisher is an unattended, autonomous news aggregation and publishing system designed to discover breaking public global news, verify editorial guidelines, format accessible visual news cards, and publish curated updates directly to the developer’s connected Instagram Professional (Business or Creator) account.

We are committed to absolute transparency. This document details what information the application accesses, how data is processed, how long it is stored, how security is maintained, and how you can exercise full control over your data, including submitting a deletion request.

2. Information We Collect and Process

The application processes strictly limited, technical, and publicly available editorial information necessary for content aggregation and publishing. It does not collect personal information from visitors or consumers.

Category Data Processed Purpose Storage Location
Public News Content Public article titles, source URLs, publication timestamps, and domain names from trusted news feeds (Reuters, AP, BBC, etc.). Editorial candidate selection, categorization, and duplicate checking. Temporary workflow memory; recorded in history.json upon publication.
Public Editorial Images Publicly licensed news imagery from Wikimedia Commons (Creative Commons / Public Domain) and associated attribution metadata. Visual rendering of 1080×1350 news cards. Ephemeral GitHub Actions runner; deployed temporarily to GitHub Pages.
Instagram Account Metadata Professional numeric account ID (user_id), Instagram handle (username), account type (BUSINESS/CREATOR), and granted permission scopes. Authenticating and routing media container creation and publication to the authorized feed. Never stored locally; queried dynamically in-memory via Meta Graph API.
Instagram Publishing Telemetry Meta container creation IDs, publication media IDs (media_id), publication timestamps, and 24-hour rate-limit quota usage via content_publishing_limit. Confirming successful publication, enforcing the 50-post/24h safety cap, and preventing duplicate posts. Persisted in history.json (media ID and timestamp only).
Generated Post Content AI-generated headlines, concise captions, and #NewsSnap hashtags created from public news summaries. Publishing accessible editorial context to Instagram. Committed to history.json as public record.
What We Do NOT Collect: NEWS SNAP Auto Publisher does not collect, track, or store personal user profiles, end-user email addresses, IP addresses, browser cookies, device telemetry, private messages (DMs), follower lists, or consumer behavioral data. The application does not display advertisements or share data with data brokers.

3. How Information Is Used

Information processed by the application is utilized solely for the following technical and editorial functions:

  • Automated Content Curation: Ingesting verified public news headlines to determine news importance and topic classification.
  • AI Text & Layout Generation: Generating factual, non-sensational summaries adhering to journalistic standards without fabricating quotes or events.
  • Deduplication Enforcement: Comparing candidate news URLs and titles against past entries in history.json and inspecting recent live feed media to ensure the same story is never published twice.
  • Rate Limit Compliance: Auditing Instagram content_publishing_limit and rolling 24-hour publication counts to strictly comply with Meta Platform Policies and avoid spam or platform degradation.
  • Image Ingestion via GitHub Pages: Hosting the generated card asset at a public HTTPS URL (https://hafizabdulbar3-creator.github.io/news-snap-automation/news_snap_post.jpg) so Meta’s media servers can ingest and process the container before publishing.

4. Third-Party Services and Sub-Processors

The application interacts with specific trusted third-party APIs under standard developer terms:

  • Meta Platforms, Inc. (Instagram Graph API): Used for account identity resolution, media container generation, container status verification, and photo publication under the Meta Platform Terms and Meta Privacy Policy.
  • GitHub & GitHub Actions (Microsoft): Automated pipeline execution, runner hosting, secrets encryption, and asset hosting through GitHub Pages under the GitHub Privacy Statement.
  • AI Inference Providers: Cloudflare Workers AI (Cloudflare, Inc.), Groq, Inc., and Google Gemini API (Google LLC). News titles and excerpts are transmitted strictly for real-time natural language classification and post generation. No personal data is transmitted to AI providers.
  • Wikimedia Commons API: Querying publicly available editorial imagery under documented Creative Commons and Public Domain licenses.

5. Credential Security and Secret Protection

The application follows strict zero-leakage security principles:

  • Encrypted GitHub Secrets: All authentication credentials, including INSTAGRAM_ACCESS_TOKEN, INSTAGRAM_ACCOUNT_ID, and AI provider tokens, are stored exclusively within encrypted repository secrets.
  • Never Hardcoded or Committed: Access tokens and private keys are never hardcoded in source code, committed to Git branches, or printed in workflow logs.
  • Automated Masking & Sanitization: All network requests, error handlers, and diagnostic scripts actively redact tokens (masking all but the first four and last four characters) to prevent leakage in continuous integration outputs.
  • Read-Only Token Scopes: The application requires only the minimal permissions necessary for its stated function: instagram_business_basic and instagram_business_content_publish.

6. Data Retention and Lifecycle

Data retention follows automated, self-pruning policies:

  • Confirmed Published Posts: Metadata for confirmed published stories (URL, headline, publication timestamp, and Meta media_id) is maintained in history.json up to a maximum cap of 500 entries for deduplication history.
  • Dry-Run Processed Entries: Test and non-publishing runs are auto-pruned from history.json after 48 hours (DRY_RUN_RETENTION_HOURS = 48).
  • Hosted Image Assets: The public card image on GitHub Pages (news_snap_post.jpg) is overwritten with each new publication cycle, ensuring older image files are not permanently hosted on the static web tier.

7. Data Deletion Instructions (User Rights)

In full compliance with Meta Platform Policy and global privacy standards, account owners and individuals have complete control over data associated with the application.

A. Immediate Revocation of Application Permissions

You may revoke the application’s access to your Instagram account at any time:

  1. Open the Instagram app on your mobile device or navigate to instagram.com/accounts/manage_access/.
  2. Go to Settings and activity → Website permissions → Apps and websites.
  3. Under the Active tab, locate “NEWS SNAP Auto Publisher” (or your associated Meta App name).
  4. Click or tap Remove. This immediately revokes all access tokens and halts all API publishing capabilities.

B. Requesting Permanent Deletion of Stored Records

If you are an author, publisher, or account administrator wishing to have specific URLs, headlines, or historical media references permanently purged from the repository’s history.json log:

  1. Via Public GitHub Issue (Recommended): Submit a deletion request at github.com/hafizabdulbar3-creator/news-snap-automation/issues with the title Data Deletion Request and provide the URL or headline to be removed.
  2. Via Verified Developer Email: Send an email to the verified repository maintainer at hafizabdulbar3@gmail.com with the subject [NEWS SNAP] Data Deletion Request.
Deletion Timeline: Upon receipt of a verified deletion request, the maintainer will manually delete the designated record from history.json, commit the change, and deploy the update within 48 hours.
